# 微信读书升级通知修复与真机验证

2026年11月18日，Leaf5 的微信连接测试将升级通知误判为连接失败。官方 Skill 已更新到1.0.6，明确要求将 `upgrade_info` 作为非阻塞通知，优先使用同一回包的业务数据。修复将升级提示与业务错误分离；这类兼容更新之后不必再单独发布 App。

## 根因与上次处理

正式 App v1.0.6（109）在 WeReadClient 中固定上报 Skill 1.0.5，九处响应判断一旦发现 `upgrade_info` 就提前返回失败，即使HTTP成功、同一回包有有效业务数据。

10月12日的8368a37提交只做了固定版本1.0.4升到1.0.5，并将面向Agent的下载Skill指令改为面向App用户的更新提示。它没有实现动态兼容处理，因此不能避免下次通知再次触发误判。README当时也明确写着不自动跟随未知版本。

官方当前规范：[Tencent WeChatReading SKILL.md](https://github.com/Tencent/WeChatReading/blob/main/skills/SKILL.md)。本次核对日期为2026年11月18日，后续主分支文档可能继续变化。书架、统计、进度与摘录能力文档也已核对。

## 修复范围

从正式 release/v1.0.6 创建 fix/weread-upgrade-notice，未带入此前待决策的PR2周期书单、数据库依赖或刷新监听实验。

- 所有网关HTTP成功响应经统一 WeReadResponsePolicy 校验。
- 非零业务错误码仍失败；错误码格式异常也失败，不把鉴权失败解释成升级通知。
- 升级通知不阻断合法业务数据，不额外重试当次请求。
- 按接口校验关键容器：书架books数组；统计totalReadTime数值和readTimes对象；进度book对象；摘录updated、reviews或items数组。
- 允许合法空数组和零时长；只有通知、没有业务数据，以及关键字段类型变化时明确失败，不默认生成零数据成功结果。
- 连接及统计测试中显示简短非阻塞说明；诊断日志只记接口、上报版本与business=valid，不输出远端通知正文或升级URL。
- 不下载、不执行远端Skill，不修改网关地址，也不盲目采用远端通知里的版本号。
- 核对兼容后将最终上报版本更新为1.0.6；免阻断能力单独使用原1.0.5完成了真机验证。

本次不改Worker、重试次数、熄屏调度、数据库开关、周期书单规则或设备保存策略。经用户确认，修复合入main和release/v1.0.6，以相同App版本1.0.6（109）替换原Release安装包，不创建新的版本。

## 自动测试与构建

4组JUnit测试通过，覆盖六类接口共35个校验场景：18个正常场景（无通知、对象通知、通知形态变化），6个实际错误场景，6个仅升级通知场景，5个字段/错误码类型异常场景。空书架、空摘录与零时长均有正常用例。最终上报1.0.6后再次运行全部通过。

testReleaseUnitTest、assembleRelease、R8、lintVital通过。测试依赖只用于本地测试，不打入正式运行时。无真实过期Key样本；鉴权失败通过合成错误响应验证，不修改用户Key制造失败。

## 免发版边界与回归重点

仅升级通知、增加可选字段或其他不影响已验证业务契约的改动，无需再次为版本通知发版。真正的必填参数、鉴权方式、返回结构或字段含义变化，仍需修改和测试App，不能承诺永远免发版。旧正式包包含提前失败逻辑，本次修复要先安装一次才会生效。

回归重点：原Key连接、本周/本月统计、混合预览、封面回退、进度和摘录；未来带通知但业务正常的回包继续成功；业务错误或只有通知的回包不能假成功。长期熄屏和跨日定时不属于本轮已完成验证。

原始日志与截图位于本机临时目录 /private/tmp/readtrace-weread-20261118-m7CWEW，含个人阅读信息，不提交到Git；临时目录不是永久归档。
